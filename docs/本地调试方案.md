# 情侣点菜 App · 本地调试方案

> 目标：把「发现 bug → 重新打 APK（20–30 分钟）」的反馈循环，压到 **改代码 → 按 `r` → 1 秒见效**。
>
> 本文档里的内容**已经在本仓库落地**（不是纸面建议）：Windows 桌面端已可通过 `run-windows.bat` 一键启动，并且**已实测构建成功**（`app\build\windows\x64\runner\Debug\couple_menu.exe`）。

---

## 一、结论先行

| | 结论 |
|---|---|
| **首选** | **路线 A：Flutter Windows 桌面端**（`run-windows.bat`）。这就是「在本机 Windows 电脑上直接跑」的答案，配置已落地且已验证可构建。 |
| **今天立刻能用** | **路线 D：USB 真机 `flutter run`**（`run-phone.bat`）。**零安装、零代码改动**，你手上那台安卓机 + 数据线就能跑，同样免打包、同样按 `r` 热重载。建议先上这个。 |
| **备选** | 路线 B：Android 模拟器。本机**没装** emulator 和 system-image，要下载 2–3GB，还要确认 BIOS 里开了虚拟化（VT）。A/D 都能跑的话没必要先搞它。 |
| **不推荐** | 路线 C：Flutter Web。**当前编译不过**（`dart:io` 在 Web 上不可用），改造量大，还会动到生产代码路径。 |

> 一句话：**日常用 A（电脑上直接跑），今天是 D（真机热重载）先把循环提速；只有在 A/D 都覆盖不到的场景才打 APK。**

### `dart:io` 分布（只影响 Web，不影响 Windows）

```
app\lib\core\api_client.dart:3    import 'dart:io'   （SocketException / HttpException 捕获）
app\lib\data\sync_engine.dart:2   import 'dart:io'   （File 删临时文件）

```

Windows 是 `dart:io` 平台，**这三处完全不用动**。它们只在「路线 C（Web）」下才会变成硬编译错误。

## 三、四条路线对比

| 路线 | 适配度 | 改造量 | 首次启动 | 热重载 | 主要风险 / 代价 |
|---|---|---|---|---|---|
| **A. Windows 桌面端**<br>`flutter run -d windows` | 中 → **已补齐** | **已做完**（见第五节） | 首次 3–8 分钟（编译 sqlite3），之后秒开 | **≈1 秒**（`r`） | 桌面窗口 ≠ 手机屏幕；无摄像头；图片压缩缺失 |
| **B. Android 模拟器（AVD）** | 高 | 需装 emulator + system-image **约 2–3GB** | 冷启动 1–3 分钟 | **≈1 秒**（`r`） | 本机未装这两组件；需 BIOS 开 VT；Windows 上模拟器性能一般 |
| **C. Flutter Web + Chrome** | 低 | **大**：3 处 `dart:io` 全要改、sqflite 要换 wasm 版、文件选择/图片预览要重写 | 1–3 分钟 | 1–2 秒（热重启） | **当前编译不过**；改动会侵入生产代码路径 |
| **D. USB 真机 `flutter run`** | **100%（就是真机）** | **0** | 首次 1–3 分钟（增量 debug 安装） | **≈1 秒**（`r`） | 需要数据线 + 手机开 USB 调试 |

### 关于「最贴近真机」

- **D 才是最贴近真机的**（它本来就是真机）。
- A 的**业务代码、数据库、网络、同步逻辑与真机完全一致**（同一份 Dart、同一套 SQLite SQL、同一个后端），差别只在**外壳**：窗口尺寸、输入方式、有无摄像头、系统生命周期。
- 所以 A 适合「改逻辑、看效果、调 UI 布局」这类占绝大多数的迭代；验收仍然回到真机。

## 四、推荐方案：A（Windows 桌面端）+ D（真机热重载）双轨

- **A 解决「在电脑上直接跑」**：不用手机、不用打包，改完按 `r` 立刻看。
- **D 解决「今天就要快」**：一个脚本 + 一根数据线，零改造，立刻把 20–30 分钟砍到 1 秒。
- 两者共用同一份代码、同一个后端（线上 `https://food.fmcoral.com/api`），互不冲突。

## 五、已经落地的改动（重要：都没有动业务逻辑）

| # | 文件 | 改动 | 对安卓的影响 |
|---|---|---|---|
| 1 | `app\windows\**（新建）**` | `flutter create --platforms=windows .` 生成的桌面端壳工程 | 无 |
| 2 | `app\pubspec.yaml` | 新增 `sqflite_common_ffi`、`sqlite3_flutter_libs`（**仅桌面端需要**） | 只是多了两个依赖；Android 走原生 sqflite，不会被用到 |
| 3 | `app\pubspec.yaml` | 新增 `hooks.user_defines.sqlite3` 块：**windows** 用本地 `sqlite3.c` 编译；**android** 用系统自带 `libsqlite.so` | ⚠️ 见下方「关于安卓构建」说明：这么配是为了**不让打 APK 依赖于访问 GitHub** |
| 4 | `app\windows\sqlite3_src\sqlite3.c/.h`（新建） | SQLite amalgamation 源码（约 9MB），给 Windows 本地编译用 | 无 |
| 5 | `app\lib\data\db_platform_io.dart`（新建） | 桌面端把 sqflite 全局工厂切成 FFI 版 | **Android 上是空操作**（`Platform.isWindows\|\|isLinux` 为 false） |
| 6 | `app\lib\data\db_platform_stub.dart`（新建） | Web 兜底空实现（条件导入），保证将来不碰 Web 也不会炸 | 无 |
| 7 | `app\lib\data\local_db.dart` | `open()` 里加一行 `initDbPlatform()` | 同上，Android 空操作 |
| 8 | `app\lib\data\sync_engine.dart` | 图片压缩抽成 `_tryCompress()`，**压缩不可用时回退传原图** | Android/iOS/macOS 压缩行为**完全不变**（原来就走同一条路，只是现在多了异常兜底） |
| 9 | `app\lib\core\config.dart` | `defaultBaseUrl` 改为 `String.fromEnvironment('BASE_URL', defaultValue: 'https://food.fmcoral.com')` | **不传 `--dart-define` 时值与改动前逐字节相同**，App 内依旧没有改地址的入口 |
| 10 | `run-windows.bat`、`run-phone.bat`（新建，仓库根目录） | 一键启动脚本 | 无 |

> 没有改任何业务逻辑、没有动 `server/`、没有推送 GitHub。
> `flutter analyze` 复跑过：全部是改动前就存在的 `info` 级提示（30 条），**没有 error / warning，新增代码零告警**。

### 关于安卓构建（这条请务必看一眼）

`sqflite_common_ffi` 会顺带把 `sqlite3` 包带进依赖树，而 `sqlite3` 有个构建钩子，
**默认行为是从 GitHub Releases 下载预编译库**——国内网络下这一步很可能失败，
那会让你原本能用的 `build apk` 也跟着挂掉。所以我把它配成了：

| 目标 | 取库方式 | 是否需要联网 |
|---|---|---|
| windows | 本地编译 `windows\sqlite3_src\sqlite3.c` | 否 |
| android | 直接用系统 `libsqlite.so`（**不下载、不编译、也不打进 APK**） | 否 |

安卓上 sqflite 走的是 `sqflite_android` 原生实现，这个系统库**实际不会被用到**，
所以这样配既不影响打 APK，也彻底不碰网络。

**如果你希望完全回到改动前的依赖树**：删掉 `app\pubspec.yaml` 里新增的两行依赖
（`sqflite_common_ffi`、`sqlite3_flutter_libs`）和整个 `hooks:` 块即可——
代价是 Windows 桌面端跑不起来，安卓行为则与今天完全一致。

## 六、一键启动

### 路线 A：Windows 桌面端

```
双击：run-windows.bat
```

启动后在**终端窗口**里操作：

| 按键 | 作用 |
|---|---|
| `r` | **热重载**（约 1 秒，保留页面状态）——日常用这个 |
| `R` | 热重启（重建全部状态） |
| `q` | 退出 |

想连自己本机起的后端（可选）：

```
run-windows.bat --dart-define=BASE_URL=http://127.0.0.1:3000
```

### 路线 D：安卓真机 USB

前置：手机「开发者选项 → USB 调试」打开 → 数据线连电脑 → 手机上点「允许 USB 调试」。

```
双击：run-phone.bat
```

脚本会先列设备再启动；多台设备时指定：

```
run-phone.bat -d <deviceId>
```

> 注意：这也是**免打包**的。它装的是 debug 增量包并常驻连接，改代码按 `r` 就热重载，**不需要** `build apk --release`。
> 只有**最终发版**才需要 `D:\dev\build_apk.bat` 打 release APK。

`app\lib\core\config.dart` 现在支持编译期宏，**默认仍然死死指向线上**：

```dart
static const defaultBaseUrl = String.fromEnvironment(
  'BASE_URL',
  defaultValue: 'https://food.fmcoral.com',

```

- **不传 `--dart-define`** → 与改动前完全一致，打 release APK 不受任何影响。
- 传了才生效，且是**编译期替换**——App 内依旧没有「填地址」的入口，原来那条设计约束（不给仿冒服务器留门、不给用户留填错的坑）依然成立。

## 八、已知限制（Windows 桌面端）

1. **没有摄像头**：`image_picker_windows` 只能打开文件选择框。菜品编辑器里「拍照」那条路在 Windows 上走不通，只能「从文件选」。
2. **图片压缩不可用**：`flutter_image_compress` 没有 Windows 实现 → 已兜底成「跳过压缩、直接传原图」。桌面端传 3–5MB 原图**可能超时**；**验证上传链路请用真机**。
3. **窗口 ≠ 手机屏幕**：默认是个桌面尺寸窗口。布局问题（小屏、刘海、超大字体）在桌面端看不出来，必须回真机验收。`main.dart` 里虽然把字体缩放钳在 0.9~1.2，但真机表现仍以真机为准。
4. **测不了系统生命周期**：切后台被杀、断网→恢复→离线队列（outbox）重放的真实时序，桌面端模拟不出来。
5. **`flutter_secure_storage` 在 Windows 上用 DPAPI**，与 Android Keystore 底层不同，但对本 App 是透明的（读写 token 的 API 一致）。
6. **首次构建会本地编译一次 SQLite**（`windows\sqlite3_src\sqlite3.c`），大概多花 1–3 分钟；之后有缓存，秒过。
7. **性能不等于真机**：debug 模式带断言、非 AOT，卡顿/内存问题请以真机 release 包为准。

## 九、哪些场景仍然必须打 APK 真机测

1. **拍照 → 压缩 → 上传**的完整链路（真大小、真耗时、弱网行为）。
2. **离线可用主线**：断网下单 → 恢复网络 → outbox 重放 + cursor 补漏是否正确收敛。
3. **进程被杀后的恢复**：本地 SQLite 副本、cursor、token 是否都在。
4. **屏幕适配**：小屏 / 全面屏 / 系统超大字体 / 横竖屏。
5. **Android 系统特性**：返回键与手势、通知、权限弹窗、后台限制。
6. **性能与体积**：启动耗时、内存占用、安装包体积。
7. **发版前**：`release` 与 `debug` 行为有差异（AOT vs JIT、断言开关、混淆），**必须打一次 release APK 完整走查**。

## 十、排错 FAQ

**Q1：`Building native assets failed` / 提到 `sqlite3.x64.windows.dll` 下载失败**
sqlite3 的构建钩子默认从 GitHub Releases 拉预编译库，网络受限时会失败。
本仓库**已经把 windows 改成用本地 `sqlite3.c` 编译、android 改成用系统库**，
（`app\pubspec.yaml` 里的 `hooks.user_defines.sqlite3`），两端都不再联网，正常不会再遇到。
如果你删掉了那个 `hooks:` 块想恢复默认，就要保证能访问 GitHub Releases。

**Q1.1：整个 Windows 路线想一键回滚**
删除 `app\pubspec.yaml` 里新增的 `sqflite_common_ffi`、`sqlite3_flutter_libs` 两行 + 整个 `hooks:` 块，
然后 `flutter pub get`。剩下的 `db_platform_*.dart`、`_tryCompress()` 在安卓上都是空操作/等价行为，留着无害。

**Q2：`.plugin_symlinks` 相关报错 / `Cannot create link`**
Flutter 在 Windows 上给插件建**符号链接**，需要「开发者模式」或管理员权限。
解决：Windows 设置 → 系统 → 开发者选项 → 打开**开发者模式**，然后删掉
`app\windows\flutter\ephemeral\.plugin_symlinks` 重新构建。

**Q3：`flutter run -d windows` 里 `r` 没反应**
确认焦点在终端窗口（不是 App 窗口）；改的是 `lib/` 下的 Dart 代码才支持热重载，改 `windows/` 下的 C++/CMake 需要重启。

**Q4：想让桌面窗口小一点像手机**
拖窗口即可；要固定默认尺寸改 `app\windows\runner\main.cpp` 里的 `initial_width/height`（改完需要重启，不能热重载）。

**Q5：手机列表为空**
检查数据线（有些线只能充电）、开发者选项里的「USB 调试」、手机上是否点了「允许调试」；再跑一次 `run-phone.bat` 看设备列表。
