## 5. 隔离边界（为什么不会炸）

| 边界 | 做法 |
|---|---|
| 端口 | 只占 `127.0.0.1:3000`（api）与 `127.0.0.1:5433`（db），**不碰 80/443/3306** |
| 内存 | 每个容器 `mem_limit` 硬上限，超额被单独 OOM，不影响宿主 |
| 磁盘 | 日志 `max-size=10m × 3`，备份只保留 3 份 |
| Nginx | **只新增一个 `server{}` 块**，未改公共 `http{}` |
| 数据 | 全部落在 `/data/couple/`，与 `/www` 完全分开 |

## 6. 已知限制

1. **`/data/couple` 需要 `o+x` 权限** —— Nginx 以 `www` 用户运行，必须能"穿过"该目录才能读到图片。已设为「只遍历、不可列出目录内容」（`drwxr-x--x`），未开放读/写。
2. **服务器需 node** —— 冒烟测试在服务器上跑过一次，为此装了 `nodejs`（`/usr/bin/node`，v20）。生产容器不依赖它，仅测试用。
3. **迁移策略是"从零建表"** —— `migrate.ts` 只判断 `users` 表是否存在。后续若要改表结构，需要手工写迁移或重建（内部应用，可接受）。
4. **未做速率限制的分布式化** —— `rate-limit.ts` 是进程内存计数，单实例够用；多实例会失效。
5. **GitHub `git push` 在本环境被网络拦截** —— 代码通过 Contents API 推送，本地与远端已验证 39 个文件逐字节一致。服务器上 `git clone` / `git fetch` 正常，日常 `git pull` 可用。

## 8. 应急操作

```bash
# 看服务状态
cd /data/couple/app/server && sudo docker compose ps

# 看日志
sudo docker compose logs -f --tail=100 api

# 重启
sudo docker compose restart api

# 手动备份
sudo docker compose run --rm backup

# 更新代码
cd /data/couple/app && sudo git pull && cd server && sudo docker compose up -d --build

# 进数据库
sudo docker compose exec db psql -U couple -d couple
```
