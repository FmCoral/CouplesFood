# 版本更新与发版

Android 端应用内自更新机制，以及每次发版要做的全部事情。1.0.7 起生效。

## 1. 机制总览

清单和 APK 都是 **nginx 静态文件**，不经过后端——发版不需要动代码、不需要重建容器：

```
服务器 /data/couple/releases/
├── latest.json                    ← 发版清单（每次发版只改这个）
└── couple-menu-<版本>-arm64.apk    ← 签名 APK，文件名带版本号
        ↓ nginx alias（见 docs/deploy/nginx-food.fmcoral.com.conf 的 /dl/ 两段）
https://food.fmcoral.com/dl/latest.json     ← no-cache，每次回源
https://food.fmcoral.com/dl/*.apk           ← immutable 长缓存（文件名带版本，内容永不变）
```

客户端 `app/lib/core/app_updater.dart` 的行为：

| 环节 | 行为 |
|---|---|
| 触发 | 启动后静默检查一次（不阻塞首屏）+ 「我的 → 检查更新」手动触发 |
| 比版本 | 清单 `versionCode` 对比安装包 `buildNumber`；异常退化比 `versionName` |
| 无新版 | 静默返回；手动检查提示「已是最新版本」 |
| 有新版 | 弹窗（版本号 + 更新说明）；`force: true` 时无「稍后」按钮 |
| 下载 | 流式写临时目录，进度条；完成后核对字节数，不符即报错丢弃 |
| 安装 | `open_filex` 以 `application/vnd.android.package-archive` 拉起系统安装器 |
| 失败 | 检查/网络失败一律静默，绝不影响正常使用；下载/安装失败提示原因 |

Windows 端不做自更新（`check()` 在非 Android 平台恒返回 null），界面锁定竖屏（AndroidManifest `screenOrientation="portrait"`）。

## 2. latest.json 格式

```json
{
  "android": {
    "versionCode": 12,
    "versionName": "2.0.1",
    "url": "https://food.fmcoral.com/dl/couple-menu-2.0.1-arm64.apk",
    "notes": "给用户看的更新说明",
    "force": false,
    "publishedAt": "2026-10-19T12:30:00Z"
  }
}
```

- `versionCode`：整数，**必须严格递增**（对应 pubspec 的 build 号）
- `force`：true = 强制更新（弹窗不可关闭），只留给必须升级的重大修复
- `notes`：直接展示给用户，写人话

## 3. 发版流程（每次照做）

```powershell
# 1) 改 app/pubspec.yaml 的 version（例：1.0.9+10，构建号必须递增）

# 2) 构建（本机环境变量需内联，未设全局）
Stop-Process -Name couple_menu -Force -ErrorAction SilentlyContinue
$env:PUB_CACHE='D:\dev\pub-cache'; $env:ANDROID_HOME='D:\dev\android-sdk'
$env:ANDROID_SDK_ROOT='D:\dev\android-sdk'; $env:JAVA_HOME='D:\dev\jdk17'
cd <项目>\app
D:\dev\flutter\bin\flutter.bat build apk --release --target-platform=android-arm64
```

```bash
# 3) 核验安装包（以包为准，别信清单——版本号不同步的坑踩过）
aapt2 dump badging build/app/outputs/flutter-apk/app-release.apk | head -1
java -jar <build-tools>/lib/apksigner.jar verify --print-certs <apk> | grep SHA-256
#    签名必须是 6c010918…5ba24e，否则新包盖不上用户手机上的旧包

# 4) 上传 + 改清单
scp <apk> root@47.250.199.11:/data/couple/releases/couple-menu-<ver>-arm64.apk
#    改写 /data/couple/releases/latest.json（versionCode/versionName/url/notes，
#    url 里的文件名必须与上传的 APK 一致）
ssh root@47.250.199.11 'chmod 644 /data/couple/releases/*'
```

5) 验证：浏览器开 `https://food.fmcoral.com/dl/latest.json` 内容正确；
   `curl -I https://food.fmcoral.com/dl/<apk文件名>` 返回 200。
6) 清理：服务器上旧 APK 留最近 2~3 个，其余删掉（每个约 28MB）。

清单改完，已装 1.0.7+ 的用户**下次启动**就会收到提示，或自行到「我的 → 检查更新」。

## 4. 签名密钥（重要）

`app/android/key.properties` 与 `app/android/app/keystore/couple-menu.keystore`
**只在开发机上，已加入 .gitignore 绝不入库**。这个 keystore 丢了，就无法再签出
能覆盖安装的更新包（Android 签名不一致只能卸载重装、丢本地数据）。
**务必把这两个文件另行备份。**

## 5. 历史注记

1.0.6 及以前的装机版没有检查更新逻辑，收不到自动提示——所以 1.0.7 是最后一次
人工发版。当前机制从 1.0.7 起生效，1.0.8 起已全程应用内升级。

**v2.0.0**：品牌更名「情侣点菜」→「食在有你」，点菜流程从订单页迁移到菜单页
（加减号选菜 + 底部购物车横幅 + 立即下单），菜单管理入口移到「我的 → 菜单」，
APK 构建改用 `--target-platform android-arm64`（62MB → 28MB）。

**v2.0.1**：下单弹窗餐次按当前时间段自动选择（早/午/晚/夜宵），新增「其他」
餐次分类（奶茶、小食等），服务端 meal_type 枚举与数据库 CHECK 约束同步扩展。
