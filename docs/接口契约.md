> 与 `docs/需求基线.md` v2.0 对应。实现必须与此一致。

## 0. 通用约定

### 0.1 基础

```
Base URL    https://food.fmcoral.com/api
Content     application/json; charset=utf-8
认证        Authorization: Bearer <accessToken>
时间        全部 ISO8601 带时区（服务端统一 UTC，客户端本地化渲染）
ID          全部 UUID 字符串
```

### 0.2 响应信封

```jsonc
// 成功
{ "data": { ... } }                       // 单对象
{ "data": [ ... ], "nextCursor": "..." }  // 列表

// 失败（RFC 9457）
{
  "type": "https://couple-menu/errors/conflict",
  "title": "CONFLICT",
  "status": 409,
  "detail": "这道菜已被对方修改，请刷新后重试",
  "errors": [{ "path": ["version"], "message": "版本不匹配" }],
  "request_id": "a1b2c3d4"
}
```

### 0.3 错误码表

| HTTP | title | 何时 |
|---|---|---|
| 400 | `BAD_REQUEST` | 请求体格式错误 |
| 401 | `UNAUTHORIZED` | 无 token / token 过期 / refresh 无效 |
| 403 | `FORBIDDEN` | 超管尝试写业务数据；未绑定却访问需绑定接口 |
| **404** | `NOT_FOUND` | **资源不存在，或存在但不属于你的 couple** |
| 409 | `CONFLICT` | version 冲突 / 状态不允许 / 邀请码无效 / 正在解散 |
| 422 | `VALIDATION_ERROR` | 字段校验失败（`errors` 给出逐字段） |
| 429 | `RATE_LIMITED` | 触发限流 |
| 500 | `INTERNAL_ERROR` | 未预期异常（不返回堆栈） |

> **重要**：越权一律 404，不返回 403。403 只用于"权限模型本身不允许"（如超管写业务数据、未绑定用户访问菜单）。

### 0.4 响应头

```
X-Request-Id    每个响应都带，便于排查
```

## 1. 认证 `/auth`

### POST `/auth/register`

```jsonc
// 请求
{ "phone": "13800000001", "password": "至少8位", "nickname": "小明", "deviceId": "uuid" }
// 200
{ "data": { "userId": "uuid", "accessToken": "...", "refreshToken": "...", "expiresIn": 900 } }
```

| 错误 | 场景 |
|---|---|
| 409 | 手机号已注册 |
| 422 | 手机号格式 / 密码长度 / 昵称长度 |

### POST `/auth/login`

```jsonc
{ "phone": "13800000001", "password": "...", "deviceId": "uuid" }
// 200 → 同上
```

- 失败统一返回 `401 手机号或密码不正确`（不区分是哪个错，防枚举）
- 限流：同一手机号 8 次/分钟

### POST `/auth/refresh`

```jsonc
{ "refreshToken": "..." }
// 200 → 新 accessToken + 新 refreshToken（旧的立即作废）
```

### POST `/auth/logout`

吊销该用户全部 refresh token。

## 2. 关系 `/couples`

### POST `/couples/invite`

生成邀请码（6 位数字，24h 有效）。若已有未过期码，直接复用返回。

```jsonc
// 200
{ "data": { "inviteCode": "520134", "expiresAt": "2026-10-19T10:00:00Z", "reused": false } }
```

| 错误 | 场景 |
|---|---|
| 409 | 已在关系中（任何非 dissolved 状态） |
| 403 | 超管账号不能绑定 |

### POST `/couples/join`

```jsonc
{ "inviteCode": "520134", "deviceId": "uuid" }
// 200
{
  "data": {
    "coupleId": "uuid",
    "partnerId": "uuid",
    "accessToken": "...",      // ← 必须换发，否则 coupleId 仍是旧值
    "refreshToken": "..."
  }
}
```

| 错误 | 场景 |
|---|---|
| 409 | 邀请码无效 / 已过期 / 不能和自己绑定 / 你已在关系中 |
| 429 | 该设备输错 5 次，锁定 1 小时 |

**服务端必须做的事（同一事务）**：
1. `SELECT ... FOR UPDATE` 锁住该邀请码对应行
2. 更新 `couples`：`member_b`、`status='active'`、`bound_at`
3. 写入 `couple_members` 两行
4. **为这对情侣创建预设**：6 个种类 + 7 个口味 + 4 道菜（冰淇淋 / 奶茶 / 火鸡面 / 螺蛳粉，含各自的种类与口味关联）
5. 追加 `sync_events`（`couple.bound`）
6. 向 A 推 WS 事件
7. 返回 B 的新 token

### GET `/couples/me`

```jsonc
// 200（已绑定）
{
  "data": {
    "coupleId": "uuid",
    "status": "active",              // active | dissolving
    "partner": { "id": "uuid", "nickname": "小红", "avatarUrl": null },
    "myRoleLabel": "饲养员",
    "partnerRoleLabel": "被饲养的",
    "boundAt": "2026-03-02T10:00:00Z",
    "dissolution": null              // 或 { "requestId", "initiatedBy", "createdAt" }
  }
}
// 200（未绑定）
{ "data": null }
```

### 2.1 解散流程

#### POST `/couples/dissolve/request`

A 发起解散申请。

```jsonc
{ "reason": "可选" }
// 200
{ "data": { "requestId": "uuid", "status": "pending", "coupleStatus": "dissolving" } }
```

| 错误 | 场景 |
|---|---|
| 409 | 已有待处理申请 / 当前不是 active 状态 |

**副作用**：`couples.status` → `dissolving`；推 `couple.dissolving` 给对方；**双方所有写接口开始返回 409**。

#### POST `/couples/dissolve/:requestId/approve`

**B（被申请人）同意** → 立即解散。

```jsonc
// 200
{ "data": { "coupleStatus": "dissolved", "dissolvedAt": "..." } }
```

| 错误 | 场景 |
|---|---|
| 403 | 发起人不能批准自己的申请 |
| 404 | 申请不存在或不属于你的 couple |

**副作用**：`couples.status='dissolved'`、`archived_at`、`dissolved_reason='mutual'`；推 `couple.dissolved`；双方收到的后续请求中 `coupleId` 失效。

#### POST `/couples/dissolve/:requestId/reject`

**B 拒绝** → 回到 `active`。

#### POST `/couples/dissolve/:requestId/withdraw`

**A 撤回**（仅发起人，仅在 pending 时）。

```jsonc
// 200
{ "data": { "status": "withdrawn", "coupleStatus": "active" } }
```

## 3. 分类 `/dish-types` `/dish-flavors`

两个维度完全对称，接口一致。

### GET `/dish-types`

```jsonc
{ "data": [ { "id": "uuid", "name": "荤菜", "sortOrder": 0, "isPreset": true, "dishCount": 12 } ] }
```

### POST `/dish-types`

```jsonc
{ "name": "硬菜" }
// 201
```

| 错误 | 场景 |
|---|---|
| 409 | 同名已存在（同一 couple 内） |

### PATCH `/dish-types/:id`

```jsonc
{ "name": "大菜", "sortOrder": 3 }
```

`isPreset = true` 的条目**允许改名**（你要的是"允许自定义"，预设只是起点）。

### DELETE `/dish-types/:id`

删除分类。**不删除菜品**，只解除关联；如果某道菜因此没有种类，它变成"未分类"（菜单页归到「其他」）。

## 4. 菜品 `/dishes`

### GET `/dishes`

查询参数：

| 参数 | 说明 |
|---|---|
| `typeId` | 按种类筛选（单选） |
| `flavorIds` | 按口味筛选，逗号分隔，**取交集** |
| `q` | 名称模糊搜索 |
| `includeUnavailable` | 默认 false |
| `updatedSince` | ISO 时间，增量拉取 |
| `limit` / `cursor` | 分页 |

```jsonc
// 200
{
  "data": [
    {
      "id": "uuid",
      "name": "红烧肉",
      "imageKey": "images/ab/cd/uuid.jpg",
      "imageUrl": "https://food.fmcoral.com/media/images/ab/cd/uuid.jpg",
      "note": "少放糖",
      "tags": ["10分钟", "妈妈的味道"],
      "type": { "id": "uuid", "name": "荤菜" },          // 可为 null
      "flavors": [ { "id": "uuid", "name": "重口" } ],
      "isAvailable": true,
      "version": 3,
      "createdBy": "uuid",
      "createdAt": "...", "updatedAt": "..."
    }
  ],
  "nextCursor": null
}
```

**筛选取交集示例**：`?typeId=X&flavorIds=P,Q` → 种类=X **且** 含口味 P **且** 含口味 Q。

### POST `/dishes`

```jsonc
{
  "id": "客户端生成的uuid（可选，离线新建必传）",
  "name": "红烧肉",
  "imageKey": "images/ab/cd/x.jpg",
  "note": "少放糖",
  "tags": ["10分钟"],
  "typeId": "uuid | null",
  "flavorIds": ["uuid", "uuid"]
}
// 201
```

| 错误 | 场景 |
|---|---|
| 409 | `id` 已存在（幂等场景，客户端视为成功即可） |
| 422 | typeId / flavorIds 不属于本 couple |
| 403 | 超管账号 |

### PATCH `/dishes/:id`

```jsonc
{
  "version": 3,              // ← 必填
  "name": "红烧肉（少糖）",
  "tags": ["10分钟"],
  "typeId": "uuid",
  "flavorIds": ["uuid"]
}
```

只提交需要改的字段（客户端靠 dirty 标记决定）。

| 错误 | 场景 |
|---|---|
| 409 | `version` 不匹配 → 客户端应拉最新并做字段级合并 |
| 404 | 菜品不存在或不属于你的 couple |

### DELETE `/dishes/:id`

软删除。历史订单不受影响。

```jsonc
// 200
{ "data": { "id": "uuid", "deletedAt": "...", "version": 4 } }
```

### GET `/dishes/changes?since=<ISO>`

增量拉取（轻量字段，用于本地对齐）。

```jsonc
{ "data": [ { "id", "name", "version", "isAvailable", "deletedAt", "updatedAt" } ] }
```

## 5. 图片上传 `/uploads`

### POST `/uploads`

`Content-Type: multipart/form-data`，字段名 `file`。

```jsonc
// 200
{ "data": { "imageKey": "images/ab/cd/9f8e....jpg", "imageUrl": "https://food.fmcoral.com/media/..." } }
```

| 约束 | 值 |
|---|---|
| 单文件 | ≤ 5MB |
| 扩展名白名单 | `.jpg .jpeg .png .webp` |
| 文件名 | 服务端重命名为 UUID，**不接受客户端文件名** |
| 存储 | `/data/images/ab/cd/<uuid>.jpg`（两级目录分摊 inode） |
| 客户端压缩 | 最长边 1600px，JPEG 质量 80% |

### GET `/media/images/*`

静态文件，`Cache-Control: public, max-age=31536000, immutable`（文件名是 UUID，内容不会变）。

## 6. 点菜 `/orders`

### POST `/orders`

```jsonc
{
  "items": [
    { "dishId": "uuid", "quantity": 1, "note": "多放辣" }
  ],
  "mealType": "dinner",
  "note": "今晚想吃",
  "etaAt": "2026-10-18T11:30:00Z"
}
// 201
{ "data": { "id": "uuid", "status": "pending", "version": 1, "createdAt": "..." } }
```

| 约束 | 说明 |
|---|---|
| `items` | 1~50 项 |
| 菜品状态 | 已删除/下架的菜 → 409 |
| 快照 | 落库时冻结 `dish_name`、`dish_image_key` |
| 正在解散 | 409 |

### POST `/orders/:id/transition`

```jsonc
{ "to": "accepted", "version": 2, "replyNote": "好嘞" }
// 200
{ "data": { "id": "uuid", "status": "accepted", "version": 3, "updatedAt": "..." } }
```

| 状态机 | 允许的目标 |
|---|---|
| `pending` | `accepted` · `rejected` · `cancelled` |
| `accepted` | `cooking` · `cancelled` · `rejected` |
| `cooking` | `served` |
| `served` | `completed` |
| 终态 | 无 |

| 错误 | 场景 |
|---|---|
| 409 | 非法跃迁 / 下单人尝试接单 / 非下单人尝试取消 |
| 409 | `version` 不匹配 |

### GET `/orders`

`?status=&limit=&cursor=`

```jsonc
{
  "data": [{
    "id", "status", "mealType", "requestNote", "replyNote",
    "requesterId", "chefId", "version",
    "items": [{ "dishId", "name", "imageUrl", "quantity", "note" }],
    "timeline": { "createdAt", "acceptedAt", "servedAt", "completedAt" },
    "createdAt", "updatedAt"
  }]
}
```

## 7. 同步 `/api/sync` 与 `/api/ws`

### GET `/sync/events?since=<bigint>`

```jsonc
{
  "data": [
    { "id": 1024, "type": "dish.updated", "entityType": "dish", "entityId": "uuid", "payload": {...}, "version": 4, "createdAt": "..." }
  ],
  "cursor": 1024
}
```

事件类型：

| type | 触发 |
|---|---|
| `couple.bound` | B 加入成功 |
| `couple.dissolving` | A 发起解散申请 |
| `couple.dissolve_rejected` | B 拒绝 / A 撤回 |
| `couple.dissolved` | 解散生效 |
| `dish.created` `dish.updated` `dish.deleted` | 菜品变更 |
| `dish.type_changed` `dish.flavor_changed` | 分类关联变更 |
| `order.created` `order.status_changed` | 订单变更 |

### WS `/api/ws`

```
连接 wss://food.fmcoral.com/api/ws
① 建立后 10s 内必须发 { "type": "auth", "token": "<accessToken>" }
② 服务端回 { "type": "ready", "coupleId": "uuid" }
③ 服务端推事件：{ "id": 1025, "type": "dish.created", "payload": {...} }
④ 客户端心跳：{ "type": "ping" } → { "type": "pong", "t": 1729... }
```

> **为什么带 `/api` 前缀**：所有 HTTP 接口都在 `/api/*` 下，Nginx 只需代理这一个前缀就能覆盖全部流量（含 WS 升级）。若 WS 单独放在 `/ws`，反代要额外开口子，部署时极易漏配 —— 实际部署时就踩过这个坑。

关闭码：

| 码 | 含义 |
|---|---|
| 4001 | 未认证 / token 无效 |
| 4003 | 未绑定关系（含已解散） |

## 10. 限流汇总

| 端点 | 限制 |
|---|---|
| `POST /auth/login` | 8 次/分钟/手机号 |
| `POST /auth/register` | 10 次/分钟/IP |
| `POST /couples/join` | 5 次/小时/设备（超限锁 1 小时） |
| `POST /admin/auth` 相关 | 5 次/10 分钟 |
| 其余 | 120 次/分钟/用户 |
