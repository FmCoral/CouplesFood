# 部署手册：food.fmcoral.com

> **目标机器**：阿里云吉隆坡 2C2G / **Alibaba Cloud Linux 3**
> **既有环境**：宝塔面板 + 7 个站点 + MySQL（3306）—— **本手册不碰它们**
> **前置**：`food.fmcoral.com` 的 A 记录已指向 `47.250.199.11`
> **部署形态**：Docker Compose 双容器（api + pg），**只监听 `127.0.0.1`**，对外由宝塔 Nginx 反代

---

## 0. 为什么是这个拓扑

服务器上 80/443 已经被宝塔 Nginx 占着，跑着 7 个站点。**任何抢占 80/443 的方案都会把别人的站点搞挂**。

```
                    公网 443 (HTTPS)
                          │
                 ┌────────▼─────────┐
                 │  宝塔 Nginx       │  ← 已有，只加一个 server{} 块
                 │  (80/443 的主人)  │
                 └────────┬─────────┘
                          │ proxy_pass http://127.0.0.1:3000
                 ┌────────▼─────────┐
                 │  api 容器         │  mem_limit 320m
                 │  Fastify :3000    │
                 └────────┬─────────┘
                          │ 内部网络
                 ┌────────▼─────────┐
                 │  db 容器          │  mem_limit 400m
                 │  PG16 :5432       │  ← 宿主映射 127.0.0.1:5433（避开本机 MySQL 3306）
                 └──────────────────┘
```

**三条铁律**：

1. **不装 Caddy** —— 它要独占 80/443，会和宝塔打架
2. **api 只绑 `127.0.0.1:3000`** —— 公网直连不进来，安全边界只有 Nginx 一层
3. **db 宿主端口用 5433** —— 3306 是已有的 MySQL，5432 留着备用，别占

## 2. 系统预检（先看清楚再动手）

```bash
# 确认发行版
cat /etc/os-release | head -3          # 期望 Alibaba Cloud Linux 3
uname -r

# 期望：80/443 是 nginx，3000/5433 空着

# 确认内存与 swap
free -h

# 已有站点（记下来，后面验证没被动过）
ls /www/wwwroot/
```

### 2.1 扩 swap 到 3G

1.8G 物理内存 + 7 个站点，不给 swap 留余量迟早被 OOM Killer 干掉。**已有 1G，加到 3G**：

```bash
# 先看现有的
swapon --show

# 追加 2G（不覆盖已有的 1G swapfile，具体路径以 swapon --show 为准）
sudo fallocate -l 2G /swapfile2
sudo chmod 600 /swapfile2
sudo mkswap /swapfile2
sudo swapon /swapfile2
echo '/swapfile2 none swap sw 0 0' | sudo tee -a /etc/fstab

free -h    # 期望 Swap 行约 3.0Gi
```

### 2.2 降低 swap 倾向

```bash
sudo sysctl vm.swappiness=10
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf
```

> 10 的含义：尽量别把热数据换出去，只在真吃紧时用。默认 60 会让 Redis/MySQL 这类缓存型进程变慢。

### 2.3 目录

```bash
sudo mkdir -p /data/couple/{images,backup,pgdata}
sudo chown -R root:root /data/couple
ls -ld /data/couple/*
```

> **不要**对 `/data/couple` 做 `chmod 777`。容器的 entrypoint 会自己 chown 需要的子目录。

## 3. 安装 Docker

服务器当前没有 Docker。装 **26.x + compose v2**：

```bash
# 用阿里云镜像源（国内/马来的下载速度差异巨大）
sudo dnf install -y dnf-utils
sudo dnf config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo

sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

sudo systemctl enable --now docker
docker --version          # 期望 Docker version 26.x
docker compose version    # 期望 v2.27+
```

### 3.1 镜像加速 + 日志轮转 + live-restore

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com",
    "https://docker.nju.edu.cn"
  ],
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" },
  "live-restore": true
}
EOF
sudo systemctl restart docker
docker info | grep -A3 'Registry Mirrors'
```

| 配置 | 为什么 |
|---|---|
| `registry-mirrors` | 直连 Docker Hub 从马来经常超时，走镜像站稳定 |
| `max-size: 10m` + `max-file: 3` | 每容器日志最多 30MB。**不设的话日志能把 40G 盘写满** |
| `live-restore: true` | 重启 dockerd 时容器不停，避免误操作把线上服务打断 |

### 4.1 生成 `.env`

```bash

```

```bash
vi .env

```

**必须改的项**：

```ini
NODE_ENV=production
PORT=3000
HOST=0.0.0.0                    # ← 容器内必须 0.0.0.0，见下文坑 1

POSTGRES_PASSWORD=<上一步生成>
DATABASE_URL=postgres://postgres:<同一个密码>@db:5432/couple_menu

JWT_SECRET=<上一步生成>
JWT_ISSUER=couple-menu

ADMIN_PHONE=18756459919
ADMIN_PASSWORD=Tao00328         # 首次启动创建；登录后立刻改
ADMIN_NICKNAME=管理员

MEDIA_ROOT=/data/images
MEDIA_BASE_URL=https://food.fmcoral.com/media
MAX_UPLOAD_MB=5

BACKUP_DIR=/data/backup
BACKUP_KEEP_DAYS=3
```

> **`DATABASE_URL` 里的 host 是 `db`**（compose 服务名），不是 `127.0.0.1`。

> **`HOST=0.0.0.0` 的原因**：compose 用 `ports: 127.0.0.1:3000:3000`，流量经 docker-proxy 从 bridge 网段转进来。若进程只绑 `127.0.0.1`，会表现为 `Connection reset by peer`——看起来像服务没起，其实是绑错了地址。**对外暴露由 `ports` 那一行锁死，容器内必须听所有网卡。**

## 6. 宝塔 Nginx 反代（**只新增一个站点，不碰其他 7 个**）

### 6.1 建站

宝塔面板 → 网站 → 添加站点：

| 项 | 值 |
|---|---|
| 域名 | `food.fmcoral.com` |
| 根目录 | 任意（如 `/www/wwwroot/food.fmcoral.com`，不会用到） |
| FTP | 不创建 |
| 数据库 | 不创建 |
| PHP 版本 | **纯静态** |

### 6.2 改配置

点站点 → 设置 → 配置文件，把 `server{}` 块替换为：

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name food.fmcoral.com;

    # 临时验证用：Let's Encrypt HTTP-01
    location /.well-known/acme-challenge/ {
        root /www/wwwroot/food.fmcoral.com;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name food.fmcoral.com;

    # 证书路径由宝塔申请后自动填入，不要手改
    ssl_certificate     /www/server/panel/vhost/cert/food.fmcoral.com/fullchain.pem;
    ssl_certificate_key /www/server/panel/vhost/cert/food.fmcoral.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers on;
    ssl_session_cache   shared:SSL:10m;
    ssl_session_timeout 10m;

    # ---- 安全头 ----
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Content-Type-Options    "nosniff" always;
    add_header X-Frame-Options           "DENY" always;
    add_header Referrer-Policy           "no-referrer" always;

    # ---- 上传大小（图片客户端已压缩，留 8M 余量）----
    client_max_body_size 8m;

    # ---- 图片静态资源直出（不经 Node，省内存）----
    location /media/ {
        alias /data/couple/images/;
        # 不要同时用 expires 和 add_header Cache-Control：
        # expires 会无条件追加一个 max-age 头，响应里就会出现两条 cache-control。
        # 图片文件名是 UUID、内容永不变化，可以放心长缓存 + immutable。
        add_header Cache-Control "public, max-age=2592000, immutable" always;
        add_header X-Content-Type-Options "nosniff" always;
        access_log off;
        try_files $uri =404;
    }

    # ---- WebSocket ----
    location /api/ws {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host       $host;
        proxy_set_header X-Real-IP  $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout  3600s;    # 长连接，别 60s 就断
        proxy_send_timeout  3600s;
        proxy_buffering     off;
    }

    # ---- API ----
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host       $host;
        proxy_set_header X-Real-IP  $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
        proxy_buffering off;          # SSE / 流式响应需要
    }

    location = / { return 404; }
    location /  { return 404; }       # 没有网页前端，只有 API
}
```

> **`X-Forwarded-Proto` 必须传**：后端据此判断是否加 HSTS 头、生成绝对 URL。漏了会导致跳转链接变成 `http://`。

### 6.3 申请证书

宝塔 → 站点设置 → SSL → **Let's Encrypt** → 勾选域名 → 申请 → **开启「强制 HTTPS」**。

```bash

```

## 7. 备份

### 7.1 脚本

`server/scripts/backup.sh` 做三件事：`pg_dump -Fc` + 导出 schema + 打包图片，合并成一个 `couple-YYYYMMDD-HHMMSS.tar.gz`，按文件名倒序**只保留最近 3 份**。

```bash
chmod +x scripts/backup.sh
sudo ./scripts/backup.sh
ls -lh /data/couple/backup/
```

### 7.2 定时任务

```bash
# 每天 03:00（避开白天的访问高峰）
( crontab -l 2>/dev/null; \
  echo '0 3 * * * cd /data/couple/app/server && /usr/bin/docker compose exec -T db pg_dump -U postgres -Fc couple_menu > /tmp/db.dump && mv /tmp/db.dump /data/couple/backup/manual-$(date +\%Y\%m\%d).dump' \
) | crontab -
crontab -l
```

> **更省事的做法**：宝塔面板 → 计划任务 → 添加 Shell 脚本，调用 `/data/couple/app/server/scripts/backup.sh`。这样日志、失败通知都由宝塔统一管理，不用记 crontab 转义。

### 7.3 恢复

```bash
cd /data/couple/app/server && sudo docker compose stop api

mkdir -p /tmp/restore
sudo tar xzf /data/couple/backup/couple-<时间戳>.tar.gz -C /tmp/restore

# 数据库
sudo docker compose exec -T db psql -U postgres -c 'DROP SCHEMA public CASCADE; CREATE SCHEMA public;'
sudo docker compose exec -T db pg_restore -U postgres -d couple_menu --no-owner /tmp/restore/db.dump

# 图片
sudo rm -rf /data/couple/images && sudo cp -a /tmp/restore/images /data/couple/images

sudo docker compose start api
curl -s http://127.0.0.1:3000/api/health
```

> 恢复前把 `db.dump` 拷进容器（`docker compose cp`），或者直接用 `cat | docker compose exec -T` 管道。上例假设你已 `cp` 过。

## 9. 故障排查

| 现象 | 排查顺序 |
|---|---|
| 502 Bad Gateway | ① `docker compose ps` 是否 Up ② `curl 127.0.0.1:3000/api/health` ③ 端口映射是否 `127.0.0.1:3000` |
| `Connection reset by peer` | 容器内 `HOST` 是不是 `0.0.0.0`（见 §4.1） |
| 上传图片 `EACCES` | entrypoint 有没有跑起来；`ls -ld /data/couple/images` |
| 证书申请失败 | 80 端口是否放行；`dig food.fmcoral.com`；`/www/wwwroot/food.fmcoral.com/.well-known/` 是否可访问 |
| 内存逼近上限 | `docker stats`；`dmesg -T \| grep -i oom`；考虑降 `shared_buffers` 或 `max_connections` |
| 其他站点挂了 | `nginx -t`；检查是否误改公共 `http{}` 块；`systemctl status nginx` |
| WebSocket 连不上 | Nginx 的 `Upgrade`/`Connection` 头是否透传；`proxy_read_timeout` 是否太短 |
| 同步不工作 | `curl 'https://food.fmcoral.com/api/sync/events?since=0'`；客户端 cursor 是否倒退 |
| 超管登不上 | `.env` 的 `ADMIN_PHONE`；重启后是否重建；`docker compose logs api \| grep admin` |

## 9.1 首次部署时真实踩过的坑（都已修复，留作对照）

这一节记录 2026-10 首次上线时实际遇到的问题。**如果你在别处重建环境又遇到同样现象，直接看这里。**

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | api 容器反复重启，日志 `relation "users" does not exist` | 代码里根本没有建表逻辑，本地测试时是手工跑的 `schema.sql`，容器化后没人跑 | 新增 `src/shared/migrate.ts`，启动时幂等执行 `schema.sql`（表已存在则跳过）。Dockerfile 增加 `COPY docs/schema.sql` |
| 2 | Docker build 报 `COPY docs/schema.sql` 找不到 | 构建上下文是 `server/`，`docs/` 在上一层，Docker 不允许 COPY 到上下文外 | compose 里 `build.context: ..`，Dockerfile 路径全部加上 `server/` 前缀 |
| 3 | 备份一秒生成一个包，把目录刷满 | `postgres:16-alpine` 是 busybox，**不支持 `date -d 'tomorrow 03:00'`**，算下次触发时间得到负数，`sleep` 失败后 while 循环空转 | 备份容器改为「跑一次就退出」，调度交给宿主机 cron（GNU date 可靠） |
| 4 | `docker compose exec backup ...` 无法执行脚本 | 容器 entrypoint 是个 `while true` 死循环，`exec` 传的命令只是被当成参数追加 | 同上。改用 `docker compose run --rm backup` |
| 5 | 图片 URL 变成 `/media/media/xxx.jpg`，取图 404 | `.env` 里 `MEDIA_BASE_URL` 填成了 `https://域名/media`，代码又拼了一次 `MEDIA_BASE_PATH` | `MEDIA_BASE_URL` 只填域名；config 里加 `refine` 校验，填错直接启动失败 |
| 6 | 图片仍在 404，Nginx 日志 `stat() failed (13: Permission denied)` | `/data/couple` 是 `750 root:root`，Nginx 以 `www` 用户跑，进不去这个目录 | `chmod o+x /data /data/couple`（只给遍历，不给读列目录）。**注意不要用 `o+r` 或 777** |
| 7 | 图片响应里有两个 `cache-control` 头 | `expires` 指令会无条件追加一个 `max-age` 头，再 `add_header` 就重复了 | 去掉 `expires`，只用 `add_header Cache-Control "... immutable"` |
| 8 | WebSocket 连 `/ws` 404 | 路由注册在 `/ws`，但 Nginx 只代理 `/api/` | 统一改成 `/api/ws`，与其余接口保持一致 |
| 9 | WebSocket `socket.on is not a function` | 用 `curl -I` 测的，HEAD 请求不会升级到 WS，handler 里拿到的是 request 而非 socket | 用真正的 WS 客户端（`ws` 包）测试 |

> **教训**：本地跑通 ≠ 容器能跑。本地是手工建库 + 手工跑脚本，容器化后这些"隐式前提"全部消失。凡是"环境里已有某个状态"的假设，都必须在启动流程里显式化。

## 10. 换服务器 IP（已装 App 不受影响）

客户端连的是**域名**，不是 IP：

1. 新机按本文档 §2-§7 装好
2. 老机跑 `./scripts/backup.sh`，把 `/data/couple/backup/` 最新包拷到新机
3. §7.3 恢复
4. 域名服务商把 `food.fmcoral.com` 的 A 记录指向新 IP
5. 等 DNS 生效（TTL 内）

**App 端零改动、零重装。** 兜底：客户端设置页保留「手动填服务器地址」，极端情况可临时指向 IP 或备用域名。
