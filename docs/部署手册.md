# 部署手册：food.fmcoral.com

> 目标机器：2C2G / Ubuntu 22.04 或 24.04 / 吉隆坡
> 前置：域名 `food.fmcoral.com` 的 A 记录已指向服务器公网 IP
> 全程约 30 分钟

---

## 0. 开工前检查

```bash
# 在本机确认 DNS 已生效（应返回你的服务器 IP）
dig +short food.fmcoral.com

# 云厂商安全组必须放行
#   22   SSH（建议只对你的 IP 开放）
#   80   HTTP（Caddy 申请证书用，必须开）
#   443  HTTPS
#   ❌ 不要开 5432、不要开 3000
```

---

## 1. 系统准备

```bash
# 更新 + 基础工具
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl git ufw ca-certificates

# 时区（服务器 UTC，客户端自行本地化；这里设成东八区便于你看日志）
sudo timedatectl set-timezone Asia/Shanghai

# 防火墙
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --force enable
```

### 1.1 **必须开 swap**（2G 内存不开会被 OOM Killer 杀进程）

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 验证
free -h
#               total        used        free      shared  buff/cache   available
# Mem:           1.9Gi       ...
# Swap:          2.0Gi   ← 必须有这一行
```

### 1.2 降低 swap 倾向（有 swap 但别过早用）

```bash
sudo sysctl vm.swappiness=10
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf
```

## 2. 安装 Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

## 3. 目录与配置

```bash
sudo mkdir -p /data/{images,backup,pgdata}
sudo chown -R $USER:$USER /data
cd /opt && sudo git clone <你的仓库地址> couple-menu
sudo chown -R $USER:$USER /opt/couple-menu
cd /opt/couple-menu
```

### 3.1 生成 `.env`（**不要提交到 git**）

```bash
cp .env.example .env

# 生成三份随机密钥
echo "JWT_SECRET=$(openssl rand -hex 32)"
echo "POSTGRES_PASSWORD=$(openssl rand -hex 16)"
echo "ADMIN_PASSWORD=$(openssl rand -base64 12)"   # 记下来，登录后自己改

nano .env
```

`.env` 必须包含：

```ini
NODE_ENV=production
PORT=3000

# 域名（Caddy 用）
DOMAIN=food.fmcoral.com

# 数据库
POSTGRES_PASSWORD=<上面生成>
DATABASE_URL=postgres://postgres:<上面生成>@db:5432/couple_menu

# 认证
JWT_SECRET=<上面生成>
JWT_ISSUER=couple-menu
ACCESS_TTL_SEC=900
REFRESH_TTL_DAYS=30

# 超管（首次启动自动创建；登录后请立刻改密码）
ADMIN_PHONE=18756459919
ADMIN_PASSWORD=<上面生成>
ADMIN_NICKNAME=管理员

# 存储
IMAGE_DIR=/data/images
MEDIA_BASE_URL=https://food.fmcoral.com/media
MAX_UPLOAD_MB=5

# 备份
BACKUP_DIR=/data/backup
BACKUP_KEEP_DAYS=3

LOG_LEVEL=info
```

> ⚠️ **`.env` 权限**：`chmod 600 .env`

## 4. 启动

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f api
```

首次启动会：

1. 创建数据库表（自动执行 `schema.sql`）
2. 用 `ADMIN_PHONE` / `ADMIN_PASSWORD` 创建超管账号
3. Caddy 自动申请 Let's Encrypt 证书（**约 30 秒**）

### 4.1 验证

```bash
# 本地健康检查
curl -s localhost:3000/health

# 外网 HTTPS（证书是否签发成功）
curl -s https://food.fmcoral.com/api/health
curl -sI https://food.fmcoral.com/api/health | grep -i strict-transport
```

若证书申请失败，检查：

```bash
docker compose logs caddy | tail -40
# 常见原因：
# ① 80 端口没开（Let's Encrypt 需要 HTTP-01 验证）
# ② DNS 还没生效（dig 不到 IP）
# ③ 域名已被墙/被占用
```

### 4.2 超管登录验证

```bash
curl -s -X POST https://food.fmcoral.com/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"phone":"18756459919","password":"<ADMIN_PASSWORD>","deviceId":"cli-test"}'
# 应返回 accessToken，且 /api/couples/me 返回 null（超管不绑定）
```

## 5. 备份

### 5.1 脚本

`scripts/backup.sh`（仓库内）：

```bash
#!/usr/bin/env bash
set -euo pipefail
STAMP=$(date +%Y%m%d-%H%M)
OUT="/data/backup/couple-menu-${STAMP}.tar.gz"
TMP=$(mktemp -d)

# 数据库
docker compose -f /opt/couple-menu/docker-compose.yml exec -T db \
  pg_dump -U postgres couple_menu | gzip > "$TMP/db.sql.gz"

# 图片
cp -a /data/images "$TMP/images"

# 打包（含清单，便于核对）
cat > "$TMP/MANIFEST.txt" <<EOF
couple-menu backup
created: $(date -Is)
db_size: $(du -sh "$TMP/db.sql.gz" | cut -f1)
images: $(find "$TMP/images" -type f | wc -l) files, $(du -sh "$TMP/images" | cut -f1)
EOF

tar czf "$OUT" -C "$TMP" .
rm -rf "$TMP"

# 只保留 3 份
ls -1t /data/backup/couple-menu-*.tar.gz | tail -n +4 | xargs -r rm -f

echo "$(date -Is) backup ok: $OUT ($(du -h "$OUT" | cut -f1))"
```

```bash
chmod +x scripts/backup.sh

# 立即跑一次验证
./scripts/backup.sh
ls -lh /data/backup/
```

### 5.2 定时任务

```bash
(crontab -l 2>/dev/null; echo '0 3 * * * cd /opt/couple-menu && ./scripts/backup.sh >> /var/log/couple-backup.log 2>&1') | crontab -
crontab -l
```

### 5.3 恢复流程（写下来，出事时不用想）

```bash
cd /opt/couple-menu
docker compose stop api

# 解包
mkdir -p /tmp/restore && tar xzf /data/backup/couple-menu-<时间戳>.tar.gz -C /tmp/restore

# 恢复数据库
gunzip -c /tmp/restore/db.sql.gz | docker compose exec -T db psql -U postgres -d couple_menu

# 恢复图片
sudo rm -rf /data/images && sudo cp -a /tmp/restore/images /data/images
sudo chown -R 1000:1000 /data/images

docker compose start api
```

## 7. **部署后第一件事：改超管密码**

```bash
# 方式一：改 .env 后重启（会重置超管密码）
nano .env          # 修改 ADMIN_PASSWORD
docker compose up -d

# 方式二：登录后用接口改
curl -X POST https://food.fmcoral.com/api/auth/change-password \
  -H "Authorization: Bearer <accessToken>" \
  -H 'Content-Type: application/json' \
  -d '{"oldPassword":"...","newPassword":"..."}'
```

> **为什么强调**：超管能解散所有情侣、能看所有菜品和订单。它必须是全系统最强的密码。

## 8. 故障排查

| 现象 | 排查 |
|---|---|
| 打不开网站 | `docker compose ps` → `docker compose logs caddy` |
| 证书报错 | 80 端口是否放行；`dig food.fmcoral.com` 是否指向本机 |
| API 502 | `docker compose logs api`；`/ready` 是否 503（DB 挂了） |
| 内存不足 / 进程被杀 | `free -h` 看 swap；`dmesg \| grep -i oom` |
| 图片 404 | 检查 `/data/images` 是否挂载进容器 |
| 同步不工作 | `curl /api/sync/events?since=0`；WS 是否被反代正确升级 |
| 超管登不上 | `.env` 的 `ADMIN_PHONE` 是否正确；重启后是否重建 |

## 9. 换服务器 IP（不影响已安装的 App）

因为客户端连的是**域名**，只需：

1. 新服务器按本文档重装
2. 在老服务器 `./scripts/backup.sh` 导出最新备份
3. 把备份拷到新服务器并恢复
4. 在域名服务商把 `food.fmcoral.com` 的 A 记录改成新 IP
5. 等 DNS 生效（几分钟到几小时）

**App 端零改动。** 兜底：设置页里保留"手动填服务器地址"，极端情况下可临时指向 IP。
